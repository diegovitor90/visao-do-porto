Inspiração metodológica: README de entrada, documento de arquitetura, diagramas
editáveis e ADRs. A geração de APIs usa código e testes como evidências, mas não
alega Spring REST Docs: esse plugin não está configurado e pom.xml foi preservado.
O PDF desta revisão é impresso do HTML pelo Chrome; não é Asciidoctor PDF/Ruby.

=== Política de atualização

Ao mudar código: revisar contratos/campos/erros, atualizar testes pertinentes,
rever estado implementado/proposto e editar fontes puml/adoc. Rodar extração,
renderização e validação; revisar HTML/PDF. Capturas históricas não devem ser
reescritas como se fossem resultados novos. Nova decisão aprovada ganha novo ADR;
hipótese continua em pendências. Registrar versão e data após revisão.

As declarações geradas e o manifesto de proveniência registram hashes das fontes.
Eles detectam alterações, mas não substituem revisão semântica dos documentos.
Scripts não fazem commit, push, instalação global ou download automático.
